# 连接与部署排错

先执行已安装 Skill 的 `scripts/fleet_skill.py doctor --name <连接名>`。默认诊断不创建浏览器；`--runtime` 会创建并清理临时空白实例，只在需要运行时验收时使用。

| 现象 | 处理方式 |
| --- | --- |
| 当前会话没有 Fleet 工具 | 查看 `setup` 的配置保存与连接探测结果；按提示重新加载或重启客户端。确认 Skill 与 MCP 都安装在当前客户端用户下，Windows 与 WSL 需分别注册。 |
| 缺少 Python、AI 客户端 CLI 或 SSH | 在客户端安装对应前置工具后重试。客户端不需要 Node.js；服务主机依赖由新部署流程补齐。 |
| SSH 认证或主机验证失败 | 用同一用户和 SSH 别名先完成正常连接，配置密钥/agent 并核实主机指纹。不要关闭主机验证或把私钥、SSH 密码发到对话中。 |
| root / sudo 或 Docker 权限不足 | 在服务主机提供 root 或免交互 sudo；不要以 root 重装整套客户端配置。rootless Docker 不受支持。 |
| 同名 MCP 或 Skill 配置冲突 | 检查现有用途。为新连接选择其他 `--name`，或由用户明确处理旧配置；不要覆盖其他服务器配置。Skill 文件冲突按安装器给出的路径处理。 |
| 已有 Docker 包冲突 | 保留现有运行时，依据包模拟结果由管理员解决。不要自动卸载 Docker/containerd、执行 prune 或替换宿主网络。 |
| 服务目录、数据目录或网络冲突 | 核实指定路径和已有 Compose 身份；一个主机只支持一套 Fleet 固定网络。不要删除不明数据、改动已有子网或重新 init 已有部署。 |
| Token 文件不可读或鉴权失败 | `--token-file` 是容器内路径，确认已挂载、权限正确且令牌仍有效；只检查状态，不打印文件内容。令牌轮换后文件必须同步更新。 |
| 本地 8080 被占用，或桌面返回 403 | 关闭占用本次转发端口的程序，或使用已有可达管理入口；访问地址必须满足 Host/Origin 配对。不要随意换转发端口或改服务允许来源。 |
| HTTPS 登录后反复掉回登录页 | 使用部署现有的 HTTPS 管理地址；带 Secure 属性的 Cookie 不适用于普通 HTTP 转发入口。 |
| 人工桌面无权访问或实例忙 | 管理页与 MCP 使用相同平台凭据；已有租约先按原流程结束。任务运行中等待可接管时机，不强制重启实例。 |
| 找不到邮箱，或网页任务拒绝执行 | 邮箱须遍历实例绑定字段，不能只用名称搜索；确认当前令牌的实例范围。绑定、登录确认和自动化模式在管理页设置。 |
| MCP 断线或结果未知 | 重新连接后先用已有 `jobId` 查询。`outcome_unknown` 先核查网站结果，不自动重新提交。 |

新部署失败时保留源码、数据与日志，处理具体失败原因后重试 `setup`；不要使用清空数据、重置密钥或自动回滚来“修复”。已有服务复用失败时，只诊断，不通过重建恢复连接。

报告诊断时包含连接名、失败阶段、错误码和脱敏路径即可。不要粘贴令牌内容、账号密码、Cookie、完整环境变量或含认证信息的 URL。
